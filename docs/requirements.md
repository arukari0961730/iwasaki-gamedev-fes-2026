# 文化祭ゲーム展示サイト 要件定義書

最終更新: 2026-10-23（文化祭版の完成時点）

公開URL: https://gamedev-fes-2026.web.app/

## 1. 目的

- ゲーム開発サークルの文化祭展示で、展示ゲームの紹介とランキングを見せる Web ページを作る
- 面接の技術アピールに使う。「なぜその技術を選んだか」「どう動いているか」「難しかった点」を説明できるようにする

## 2. スケジュールと進め方

| フェーズ | 時期 | 方針 | 状態 |
|---|---|---|---|
| 文化祭版 | 2026-10-23 に開発、10-24 本番 | 当日ちゃんと動くことを最優先にする | **完成・運用終了**（10-26 にスコア登録の受付を締め切り） |
| 面接版 | 文化祭のあと | 機能の追加と、仕組みの理解を深める作業 | 進行中 |

- 開発者: 1人
- 面接では「期限に合わせて範囲を絞って出し、実際に使って見えた課題をもとに改善した」と説明する

## 3. 利用シーン

| 場所 | 端末 | 使い方 |
|---|---|---|
| 会場 | モニター 1台（PCのブラウザで全画面表示） | `/display` を開いたままにする。誰も操作しない |
| 来場者 | 自分のスマホ | 印刷したQRコードからトップページを開く。ゲーム一覧から遊んだゲームを選び、ランキングを見る・スコアを登録する |

- QRコードは**トップページ用の1枚だけ**を印刷する（必要ならテーブルの数だけ部数を増やす）

## 4. 画面

| 画面 | URL | 内容 | ファイル |
|---|---|---|---|
| トップ | `/` | 上部に注目エリア、下部にゲーム一覧 | `public/index.html` |
| ゲーム別ランキング | `/ranking?game=<ゲームID>` | そのゲームの全順位と、スコア登録ボタン | `public/ranking.html` |
| スコア登録 | `/register?game=<ゲームID>` | 名前とスコアを入力して登録 | `public/register.html` |
| モニター表示 | `/display` | 注目エリアだけを画面いっぱいに大きく表示 | `public/display.html` |
| 管理画面 | `/admin` | 管理者のみ。記録の修正・非表示 | `public/admin.html` |

`firebase.json` の `cleanUrls` により、`ranking.html` を `/ranking` のように `.html` なしで開ける。

## 5. 機能要件

### 5.1 トップページ

**上部：注目エリア**（`public/js/carousel.js`。トップとモニター表示で共通の部品）
- ランキングのあるゲームについて、「ゲームの紹介＋TOP3」を順番に表示する
- 10秒ごとに自動で次のゲームに切り替える
- 矢印ボタン・ドット・スワイプでも切り替えられる。触ったら20秒間は自動切り替えを止める（読んでいる途中で変わらないように）
- TOP3 はリアルタイムで更新される

**下部：ゲーム一覧**
- 全ゲームの名前・画像・紹介文を表示する
- ランキングのあるゲームは「RANKING」のバッジを付け、カード全体をランキングページへのリンクにする

### 5.2 ランキング

- トップでは各ゲームの TOP3 を、ゲーム別ランキングページで全順位を表示する
- **同じ人の判定は名前だけで行う**。表示するのはその人の最高スコアだけ
- **同点の場合は、先にそのスコアを出した人を上位にする**
- データが変わったら、開いている画面に自動で反映する（Firestore の `onSnapshot`）
- 登録直後にランキングページへ移ったときは、自分の行を点滅させる（登録した名前は `sessionStorage` に一時的に保存し、URL には載せない）

### 5.3 スコア登録

- プレイヤーが自分のスマホで、名前とスコアを入力して登録する
- 名前は12文字まで
- スコアの入力欄はゲームの種類によって変える
  - 点数：数字キーボードで入力
  - タイム：数字だけを打つと自動で「:」が入る（`212` → `2:12`）。右から2桁を秒とする。秒が60以上ならエラーにする
- 同じ名前ですでに記録がある場合、前より良いスコアのときだけ上書きする。良くなければ「記録は○○のままです」と表示する
- スコアの範囲チェック、連続投稿の制限は行わない（善意を前提にし、管理画面で対応する）

### 5.3.1 受付の締め切り（文化祭のあと）

- 文化祭が終わったので、スコア登録の受付を締め切った。ランキングは「文化祭当日の最終結果」として表示を続ける
- 切り替えは2か所で行う
  - `public/js/config.js` の `ENTRY_OPEN`：画面の表示（登録ボタンを消す、トップに「GAME OVER」、登録画面に受付終了の案内、ランキングの見出しを「FINAL RESULT」に）
  - `firestore.rules` の `entryOpen()`：実際に登録を止める。画面を経由しない書き込みも拒否される（確認済み）
- 受付を再開するときは、両方を `true` に戻して公開する

### 5.4 NGワードチェック

| フェーズ | 方法 |
|---|---|
| 文化祭版（実装済み） | 画面側（`public/js/name-check.js`）で単語リストと照合する。照合の前に表記をそろえる（全角／半角＝NFKC、大文字／小文字、カタカナ→ひらがな、スペース・記号・長音の除去）。例：「ﾊﾞ カ」も「ばか」として弾ける |
| 面接版 | サーバー側（Cloud Functions）に移し、単語リスト → AI判定（Claude Haiku 5.5）の2段階にする |

- 文化祭版は画面側のチェックなので回避は可能。漏れたものは管理画面で非表示にする
- 面接版の AI 判定の方針
  - API キーはサーバー側だけで使い、画面側のコードには置かない
  - 名前は判定対象のデータとして渡し、返答は OK／NG の決まった形だけを受け付ける（AI を騙す入力への対策）
  - AI が応答しないときは登録を通し、あとで管理画面で対応する
  - API の利用額に上限を設定する

### 5.5 管理画面

- 管理者（自分）のアカウントでログインしたときだけ使える（Firebase Authentication のメール／パスワード）
- ゲームを選ぶと、非表示のものも含めた全記録が表示される
- 名前やスコアを修正できる（タイムは「分:秒」で入力）
- 不適切な記録を非表示にできる。データは消さずに `hidden: true` の印を付ける（間違えても戻せるように）
- 画面を隠しているだけでは守れないので、実際の制限はセキュリティルールで行う
- 記録を完全に削除したいときは、Firebase コンソールから行う

## 6. データ設計

### 6.1 ゲーム情報（データファイルで管理）

ゲーム情報はページに直接書かず、`public/data/games.json` にまとめる。ページはそれを読み込んで自動で並べる。**ファイル内の順番がそのまま表示順**になる。

```json
{
  "id": "warp-room",
  "name": "WarpRoom!",
  "image": "images/games/warp-room.webp",
  "description": "ワープし続けるあなたのやることは5秒耐えるだけ\nギミック満載の部屋から生き残り続けろ！！",
  "ranking": {
    "enabled": true,
    "order": "desc",
    "format": "points",
    "unit": "部屋"
  }
}
```

| 項目 | 意味 |
|---|---|
| `id` | URL に使う英数字。**一度決めたら変えない**（QRコードやランキングデータの保存場所がずれるため） |
| `image` | 画像のパス。なければ「NO IMAGE」の仮画像を出す |
| `description` | 紹介文。`\n` の位置で改行する |
| `ranking.enabled` | ランキングがあるかどうか。`true` のゲームだけが注目エリアとランキングの対象になる |
| `ranking.order` | `desc`: 大きいほど上位 / `asc`: 小さいほど上位 |
| `ranking.format` | `points`: 点数 / `time`: タイム（分:秒） |
| `ranking.unit` | 表示する単位（点、回、部屋、Coin など）。英字の単位は数字との間に半角スペースを入れる |

- 「並び順」と「表示形式」を分けておくことで、組み合わせを変えるだけで新しいパターンに対応できる
- ゲーム名はサークルのメニューの表記を正とする

**現時点のスコアのパターン**

| パターン | 種類 | 上位の条件 | 表示 |
|---|---|---|---|
| 点数 | 点数 | 高いほど上位 | 1,200点 / 12回 / 17部屋 / 1,200 Coin |
| タイム | タイム | 長いほど上位 | 2:12 |

### 6.2 スコア（Firestore で管理）

保存場所: `games/{ゲームID}/scores/{プレイヤー名}`

- **プレイヤー名をそのまま文書のIDにしている**ので、同じ名前の記録は自然に1つにまとまる（「同じ人は名前で判定し、最高スコアだけ残す」をデータの形で実現している）
- スコアはどのゲームでも**整数の数値1つ**として保存する
  - 点数はそのまま保存する（1200）
  - タイムは**秒に変換して**保存する（2:12 → 132）
- 並べ替えは数値の大小だけで行い、表示するときにゲームの設定に合わせて変換する

| 項目 | 内容 |
|---|---|
| `gameId` | どのゲームの記録か |
| `name` | プレイヤーの名前（文書のIDと同じ） |
| `score` | 整数 |
| `achievedAt` | 最高スコアを出した日時。サーバーの時刻で記録する（同点時の順位に使う） |
| `hidden` | 管理者が非表示にしたかどうか |

- 登録はトランザクションで行う（「今の記録を読む → 良ければ書く」を、他の人の登録と混ざらないように1回の処理として行う）
- ランキングの読み込みには複合インデックス（`hidden`＋`score` 降順＋`achievedAt` 昇順）を使う。定義は `firestore.indexes.json`

## 7. 技術構成

| 役割 | 使うもの |
|---|---|
| 画面 | HTML / CSS / JavaScript（React は使わない。ビルドの工程もなし） |
| Firebase の読み込み | 公式の配布場所（CDN）から ES モジュールとして読み込む。バージョンは出たばかりのものを避けて 12.19.0 に固定 |
| サイトの公開 | Firebase Hosting |
| データベース | Firebase Firestore（Standard エディション、東京リージョン `asia-northeast1`） |
| 管理者ログイン | Firebase Authentication（メール／パスワード） |
| サーバー側の処理（面接版） | Firebase Cloud Functions |

**開発用のスクリプト**

| コマンド | 内容 |
|---|---|
| `npm.cmd run images` | `素材/画像/<ゲームID>.png` を横幅1280px・WebP に変換して `public/images/games/` に書き出す（`scripts/optimize-images.mjs`） |
| `npm.cmd run qr` | 印刷用の QR コードページ `docs/qr/index.html` を作る（`scripts/make-qr.mjs`） |
| `node scripts/dev-server.mjs` | 確認用の簡易サーバー（http://localhost:5173） |
| `npx.cmd firebase deploy` | 公開する |

- 公開URLは無料のアドレス（`gamedev-fes-2026.web.app`）を使う。独自ドメインは使わない
- 文化祭版は Firebase の無料プラン（Spark）で、クレジットカードの登録なしで作った
- 面接版で Cloud Functions と AI 判定を使うときは、従量課金プラン（Blaze）とクレジットカードが必要になる

## 8. セキュリティ

Firebase では自分のサーバーを持たず、画面から直接データベースにつながる。そのため、**Firestore のセキュリティルール（`firestore.rules`）が唯一の門番**になる。

| 操作 | 誰ができるか・条件 |
|---|---|
| 1件の読み込み | 誰でも（登録時に前の記録と比べるため） |
| 一覧の読み込み | 誰でも。ただし非表示の記録は管理者だけ |
| 新規登録 | 誰でも。項目が過不足なくそろい、名前が1〜12文字で文書IDと一致し、スコアが整数で範囲内、日時がサーバー時刻、`hidden` が `false` のときだけ |
| 上書き | 誰でも。ただし変えられるのはスコアと日時だけで、**前より大きいスコアのときだけ** |
| 削除・非表示・名前変更 | 管理者だけ |

**確認済みの攻撃（すべて拒否された）**: 前より低いスコアでの上書き、プレイヤーによる非表示化、13文字以上の名前、日時の偽装、削除、非表示を含む一覧の読み込み

**注意**: 今のランキング対象ゲームはすべて「大きいほど上位」なので、上書きの条件を `>` で書いている。「小さいほど上位」のゲームを追加するときはルールの見直しが必要。

**その他**
- 名前などを画面に出すときは HTML として解釈されないようにエスケープする（他人の画面でスクリプトを動かされるのを防ぐ）
- `firebaseConfig` の `apiKey` は「どのプロジェクトにつなぐか」の名札で、公開して問題ない

## 9. 非機能要件

- **デザイン**: ゲームセンター（アーケード）風。黒背景、ブラウン管の走査線、「1UP / INSERT COIN / HI-SCORE」の表示、ドット風フォント（Press Start 2P、DotGothic16）、黄・赤・水色の3色。1〜3位は金・銀・銅色
- **スマホ対応**: 幅760px以下では1列のレイアウトにする
- **モニター表示**: 文字の大きさを画面幅に合わせて大きくする
- **画像**: 形の違う画像（縦長・正方形）も切れずに収まるよう `object-fit: contain` で表示する。横幅960px・画質70の WebP に変換（21本で合計約350KB）。上部の切り替え表示は、表示中と次のゲームの画像だけを読み込む
- **無料枠**: Hosting の転送量は1日あたり約360MB。1人目の訪問で約200〜300KBなので、1日1,000人以上の初回訪問に耐えられる見込み
- **キャッシュ**: HTML・JS・CSS・JSON は開くたびに最新かを確認する（`no-cache`）。画像は1時間ブラウザに保存させる
- **費用**: 無料枠の範囲に収める
- **公開期間**: 文化祭のあとも、面接で見せるために公開を続ける

## 12. 設計判断の記録

面接で「なぜそうしたか」を説明するための記録。

| 判断 | 検討した選択肢 | 選んだもの | 理由 |
|---|---|---|---|
| スコアの登録方法 | A. ゲームから自動送信 / B. スタッフが入力 / B＋QRで名前登録 / C. プレイヤーが入力 | C＋管理画面での修正 | Bは名前の聞き取りが難しく、B＋QRはQR発行の手間がかかる。お祭りの場なので善意を前提にし、問題があれば管理画面で直す |
| 不正対策 | 範囲チェック / 連続投稿の制限 / NGワード / 管理画面 | NGワード＋管理画面＋セキュリティルール | 当日の運用で対応できる範囲は管理画面に任せ、手間と効果のバランスをとった。データの形とスコアの上書き条件はルールで守る |
| 同じ人の判定 | 名前のみ / 端末のみ / 名前＋端末 | 名前のみ | 一番シンプル。同じ名前の別人がいても管理画面で直せる |
| 同じ人の記録のまとめ方 | 全記録を保存して表示時に集計 / 名前を文書IDにして1件にまとめる | 名前を文書IDにする | 表示のたびに集計しなくてよく、読み込み回数（＝無料枠の消費）も少ない。「前より良いときだけ上書き」もルールで書ける |
| 詳細ランキングの見せ方 | モーダルのみ / 専用URL | 専用URL | 直接開ける、スマホの「戻る」で自然に閉じられる、更新しても同じ画面のまま |
| ゲーム情報の管理 | データファイル / 管理画面から登録 | データファイル | 更新するのは自分だけで、当日はほぼ変わらない。画像アップロードの機能も不要になる |
| スコアの保存形式 | 小数 / 文字列 / 整数 | 整数（タイムは秒に変換） | 並べ替えが単純になり、計算の誤差も出ない |
| タイムの入力方法 | 分と秒の別々の欄 / `2:12` を手入力 / 数字だけで自動整形 | 数字だけで自動整形 | スマホの数字キーボードには「:」がないことが多い。数字キーボードのまま入力できる |
| 画面の技術 | React / HTML・CSS・JavaScript | HTML・CSS・JavaScript（ビルドなし） | 期限が1日しかなく、慣れていない技術で詰まるリスクを避けたい。自分で説明できるコードにしたい |
| サーバー側 | 自分でサーバーを立てる / Supabase / Vercel など / Firebase | Firebase | 公開・データベース・ログイン・リアルタイム更新がそろう。カード登録なしで始められる。Supabase は無料プランだと使わない期間に止まるため、文化祭後も公開し続ける目的に合わない |
| Firestore のエディション | Standard / Enterprise | Standard | 無料プランで使え、リアルタイム更新が使える |
| データベースの場所 | 各リージョン | 東京（asia-northeast1） | 利用者が日本にいるので通信が速い。あとから変更できないので最初に決めた |
| NGワードチェックの場所 | 画面側 / サーバー側 | 文化祭版は画面側、面接版でサーバー側 | サーバー側の処理には有料プランが必要。期限とコストを考えて段階的に進める |
| 独自ドメイン | 使う / 使わない | 使わない | 設定の反映に時間がかかることがあり、QRコードの印刷に間に合わないおそれがある。今回の用途では無料のアドレスで十分 |
| デザイン | ネオン / アーケード / レトロ / お祭り / ネオン×アーケード | アーケード | 見本を作って比較した。「ランキング」というテーマと一番相性がよく、暗い背景でゲーム画像が映える |
| モニター表示 | 別のページを作る / 同じ部品を使い回す | 同じ部品を使い回し、`/display` で表示モードだけ変える | 作る手間がほぼ増えず、見た目もそろう |
| 画像の形式 | 元の PNG / WebP に変換 | WebP（横幅960px・画質70） | 会場の電波が弱くてもすぐ表示できるよう、合計約6.7MB→約350KBに軽量化。最初は1280pxで作ったが、無料枠の転送量（1日約360MB）を見積もると来場者が多い日に足りなくなるおそれがあったため、軽量版を別に作って見比べ、問題ないことを確認してから切り替えた |
| QRコードの枚数 | ゲームごと（13枚） / トップ用＋登録用（2枚） / トップ用だけ（1枚） | トップ用だけ | ゲームごとだと印刷・設置が大変で、ゲームが増えるたびに作り直しになる。一覧から選ぶ手間は1回だけ |
| 文化祭後の扱い | 登録を受け付け続ける / 登録だけ締め切る / サイトを閉じる | 登録だけ締め切る | 面接用に公開は続けたいが、受付を開けたままだと荒らされるおそれがある。当日の結果として残せば、実際に使われた記録として見せられる。画面の表示とルールの両方で止めた |
| ゲームID | ゲーム名の変更に合わせて変える / 変えない | 変えない | URL とデータの保存場所に使っているため。名前（表示）とID（仕組み）を分けておいたので、名前だけ自由に直せた |

## 13. 開発中に起きた問題と解決

| 問題 | 原因 | 解決 |
|---|---|---|
| 公開直後、ランキングが「---」のまま表示されなかった | 複合インデックスが Firebase 側で作成中だった（約2分半） | 作成が終わるまで待った。インデックスが必要な理由（複数の条件で並べ替えるため）も理解した |
| ゲームを追加したあと、一部のPCだけトップページが空になった | ブラウザが古い JS を1時間保存（キャッシュ）しており、新しい HTML と食い違ってエラーになった | ファイルの種類ごとにキャッシュの設定を分けた（HTML・JS・CSS・JSON は毎回確認、画像は保存）。当日の更新でも起きないようにした |
| スクリーンショットに Windows の通知が写り込んでいた | 撮影時に通知が出ていた | 画像の下側を切り取って使った（元画像は `素材/元画像` に保存） |
| PowerShell で `npx` が動かなかった | Windows のスクリプト実行ポリシーで `.ps1` が止められた | 安全設定は変えず、`npx.cmd` で呼び出した |
